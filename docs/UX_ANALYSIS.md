## 1. Резюме

Продукт **крепкий по экранам, но рвётся по стыкам**. Отдельные экраны аккуратны (чистые
таблицы, консистентные тосты и лоадеры, переведённые ошибки, рабочий визард аватара). Но
**сквозной путь «регистрация → работающий аватар» нигде не ведётся за руку**: нет онбординг-
чеклиста, а на ключевых стыках (после загрузки документов, после подключения Telegram) нет
подсказки «что дальше». Главный риск — **активация**: новый пользователь попадает на пустой
дашборд и должен сам собрать продукт из 5 разрозненных шагов.

**Светофор по флоу:**

| Флоу | Статус | Одной фразой |
|---|---|---|
| Активация (signup → первый ответ) | 🟡 | Проходима, но без проводника; обрывы на 2 стыках |
| Создание проекта | ✅ | Чистая форма, авто-URL, ведёт в обзор с Quick Actions |
| Создание аватара | 🟡 | Хороший визард, но 4 шага до ценности |
| Наполнение документами | 🟡 | Статус индексации есть; нет моста «теперь в чат» |
| Тест в чате (aha) | ✅ | Работает, новый AIInput, приветствие |
| Выпуск в Telegram | 🟡 | Setup-инструкция есть; нет «проверь бота» после |
| Наблюдение (сессии/диалоги) | 🟡 | Пустые состояния без объяснения |
| Команда | 🟡 | Пустой `/members` — голая таблица (тупик) |
| Биллинг/лимиты → заявка | 🟡 | Заявочная модель; уведомление об одобрении неясно |
| Возврат после релогина | 🔴 | `?redirect=` игнорируется — теряется контекст |

**Метрики сейчас (оценка):** кликов до первого ответа аватара (aha) — **~14 + 4 шага визарда**;
обрывов на пути активации — **3** (после создания аватара, после загрузки доков, в пустых
состояниях); находок — **2 blocker-зоны риска · 8 major · 8 minor**; user stories закрыто
полностью — **~70%**, частично — **~25%**.

**Суть редизайна (1 фраза):** добавить **онбординг-чеклист до первого ответа**, заполнить
**next-step на стыках**, **упростить создание аватара** (1 поле + дефолты) и **вынести админку**
из общего сайдбара — это снимает 80% трения активации.

## 2. Бизнес-контекст и акторы

**Продукт:** SaaS для создания AI-консультантов («аватаров»), отвечающих по документам клиента
(RAG) в Telegram и на сайте. Монетизация — планы/лимиты токенов, заявочный апгрейд, админ-панель.

**Ценность:** «загрузил документы → аватар консультирует моих клиентов в Telegram → я слежу за
диалогами и расходом».

| Актор | Роль (код) | Главная цель | Где |
|---|---|---|---|
| Гость | — | понять продукт, зарегистрироваться | `/`, `/login`, `/register` |
| Владелец | `owner` | собрать аватара и выпустить его | `/projects/*` |
| Член команды | `manager/content_manager/viewer` | работать в рамках прав | `/projects/[id]/*` |
| SAAS-админ | `saas_admin` | управлять платформой, заявками, биллингом | `/admin/*` |
| Конечный клиент | `client` / end-user | (вне UI) пишет боту; его диалоги тут видны | объект наблюдения |

Роли подтверждены `[по коду]`: платформенные `saas_admin/owner/manager/content_manager/client`
(`authStore.ts:54-70`), проектные права через флаги `can_manage_*` (`PermissionCheckboxes.tsx`).

## 5. Сквозные флоу с разрывами

**Активация** (см. карту выше) — главный приоритет.

**Наполнение документами** `[вживую]`: загрузка → статус `Готов`/прогресс по этапам
(pending→parsing→chunking→embedding) ✅ `DocumentRow.tsx:50-103`; тост `«файл загружен»` ✅.
Разрыв: после `Готов` ничего не зовёт в чат (F-02).

**Выпуск в Telegram** `[вживую + по коду]`: пустой setup даёт 3-шаговую инструкцию
(`@BotFather` → токен → вставить, `TelegramSetupForm.tsx:121-130`) ✅; требует выбора аватара ✅.
Разрыв: после подключения нет «открой @bot / отправь тест» (F-04).

**Команда** `[по коду]`: пустой `/members` = голая таблица без empty-state (`MembersTable.tsx:32`)
— тупик (F-05). Добавление участника → диалог закрывается + тост ✅.

**Биллинг/лимиты** `[вживую + по коду]`: лимит → диалог `token-limit-dialog`; апгрейд = создать
`plan-request` → админ одобряет в `/admin/requests`. Разрыв: пользователю неясно, как он узнает
об одобрении (push нет) (F-19).

**Релогин/сессия** `[по коду]`: middleware кладёт `?redirect=` (`middleware.ts:45`), но `LoginForm`
его не читает, `useAuth.ts:57` всегда `router.push("/projects")` → контекст теряется (F-01).

## 8. Дизайн-направление (north-star)

**«Доведи до первого ответа за 3 шага, остальное — потом».** Продукт должен ощущаться как
рельсы: с момента входа виден **чеклист активации**, на каждом экране — **одно главное
действие**, а вся настроечная сложность (промпты, модель, оформление) **берётся системой по
дефолту** и открывается по желанию. Цель — сократить путь до «аватар ответил по моему
документу» с ~14 кликов до ~5.

Опорные принципы: **Закон Теслера** (сложность настройки несёт система, не пользователь —
дефолтные промпт/модель) · **Закон Хика** (меньше пунктов и шагов) · **Эффект пика-конца**
(праздновать первый ответ и публикацию) · **Онбординг — это дизайн** (чеклист + объясняющие
пустые состояния) · **Поток без обрывов** (next-step на каждом стыке).

Эталоны: **Chatbase** (бот из документов за 2 шага), **Linear/Vercel** (онбординг-чеклист и
живые пустые состояния), **Stripe** (ясность лимитов/биллинга), **Intercom** (инбокс диалогов).

## 9. Целевая информационная архитектура

**Проблема `[вживую]`:** на глубине аватара в сайдбаре стоят **4 группы сразу** — `Проекты` +
контекст проекта (`Обзор/Аватары/Участники/Аналитика/Telegram/Настройки`) + `АВАТАР`
(`Настройки/Документы/Чат`) + `АДМИНИСТРИРОВАНИЕ` (8 пунктов). Это стена (Хик/Миллер). Админ-
секция гейтится корректно, но всё равно мешает продуктовой навигации у админов-операторов.

```
БЫЛО (один сайдбар, до 4 групп, ~20 пунктов у админа)        СТАЛО
─────────────────────────────────────────────              ─────────────────────────────────
Проекты ▸ [проект] ▸ [контекст проекта]                     Топ-бар: [Switcher проекта ▾]  [⚙ Аккаунт ▾]  [🛡 Админка*]
АВАТАР ▸ Настройки/Документы/Чат                            Сайдбар = ТОЛЬКО контекст проекта:
АДМИНИСТРИРОВАНИЕ ▸ 8 пунктов                                  Обзор · Аватары · Участники · Аналитика · Telegram · Настройки
Внизу: Токены/Уведомления/Профиль/Помощь                   Экран аватара: под-навигация — ТАБЫ (Документы/Чат/Настройки),
                                                              не группа в сайдбаре
                                                            Админка — отдельная зона (вход из топ-бара*, только saas_admin)
```

Ходы: (1) **глобальный switcher проекта** в топ-баре вместо вложенности; (2) **навигация
аватара — табами** на его странице (как уже сделано в деталях аватара), убрать группу «АВАТАР»
из сайдбара; (3) **админка — отдельный раздел** (переключение контекста, а не 8 пунктов всегда
на виду); (4) три «Настройки» переименовать однозначно: **Профиль** (аккаунт) · **Настройки
проекта** · **Админка** (платформа).

## 10. Редизайн ключевых флоу (before → after)

### 10.1 Онбординг-чеклист активации (F-07) — ГЛАВНОЕ

**Сейчас:** новый юзер → `/projects` пуст, одна кнопка «Создать проект», дальше сам.
**Предлагаю:** на дашборде, пока аватар не «живой», — карточка-чеклист с прогрессом; каждый шаг
завершается → галка → подсвечивается следующий. Исчезает после завершения.

```
┌─ Запусти первого AI-консультанта ───────────── 1 / 4 ✓ ─┐
│  ✓ 1. Создать проект                                     │
│  ◉ 2. Создать аватара                      [ Создать → ] │  ← один primary CTA
│  ○ 3. Загрузить документы                                │
│  ○ 4. Опубликовать в Telegram                            │
│  ──────────────────────────────────────────────────────  │
│  💬 Подсказка: после загрузки документов аватар сразу     │
│     ответит в тестовом чате.                              │
└──────────────────────────────────────────────────────────┘
```
**Почему проще:** Zeigarnik (видимый прогресс тянет завершить) + узнавание (следующий шаг
показан, не надо искать) + онбординг-как-дизайн. **Эффект:** кликов-до-aha ↓, % новых,
дошедших до первого ответа, ↑ (§12).

### 10.2 Мост «документы → чат» (F-02) и «аватар → документы» (F-03)

**Сейчас:** после индексации «Готов» — тишина; после создания аватара — деталь без зова дальше.
**Предлагаю:** контекстный баннер на странице аватара/документов, реагирующий на состояние:

```
Аватар создан, документов нет:   [ ⬆ Загрузить документы ]   ← primary
Документы готовы (Готов):        ✓ База знаний готова.  [ 💬 Открыть тестовый чат ]
В чате после первого ответа:     ✓ Работает! Следующий шаг → [ Опубликовать в Telegram ]
```
**Почему проще:** поток без обрывов + пик-конца (празднуем «работает!»). **Эффект:** доля
аватаров, доведённых до тест-чата и публикации, ↑. **Цена:** S (одна реактивная плашка).

### 10.3 Упрощение создания аватара (F-09)

**Сейчас:** визард 4 шага (Основное → Промпты → Внешний вид → LLM) до создания.
**Предлагаю:** один экран — **только имя** (+ авто-описание); промпт, модель, оформление —
дефолтные, спрятаны под «Расширенные настройки». Создать → сразу экран «Загрузить документы».

```
┌─ Новый аватар ───────────────────────────────┐
│  Имя*            [ Консультант по продуктам  ] │
│  ▸ Расширенные настройки (промпт, модель, вид) │  ← прогрессивное раскрытие
│                              [ Создать аватар ]│
└────────────────────────────────────────────────┘
```
**Почему проще:** Теслер (дефолты несёт система) + вычитание (4 шага → 1) + прогрессивное
раскрытие. **Эффект:** шагов до создания 4→1; полей обязательных — 1.

### 10.4 Завершение публикации в Telegram (F-04)

**Сейчас:** подключил бота — статусы есть, но «дальше?» нет.
**Предлагаю:** после успешного connect — success-блок: **[ Открыть @bot в Telegram ]** (deep-link
`t.me/<bot>`) + **[ Отправить тестовое сообщение ]** + «Готово, аватар отвечает клиентам».
**Почему:** пик-конца — финал флоу должен ощущаться победой. **Цена:** S.

### 10.5 Живые пустые состояния (F-05/F-06)

**Сейчас:** `/members` — голая таблица; sessions/users/requests — «нет данных» без контекста.
**Предлагаю:** единый `EmptyState` везде; для **пассивных** списков (наполняются извне) — текст-
объяснение + релевантное действие:

```
Сессии:   🗨  «Здесь появятся диалоги, когда клиенты напишут боту.»  [ Подключить Telegram ]
Участники:👥  «Пока вы один в проекте.»                              [ Пригласить участника ]
Заявки:   📥  «Новых заявок нет.»                                    (без CTA — пассивный)
```
**Почему проще:** убирает `orphan-state` — пустота объясняет себя и зовёт к действию.
