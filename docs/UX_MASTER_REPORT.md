## 1. Резюме и вердикт

Продукт **аккуратен поэкранно, но ядро сквозного флоу сейчас сломано на дефолтах**. Отдельные
экраны чисты (таблицы, тосты, лоадеры, статусы индексации, пустые состояния с CTA, страница
тарифа). Но **путь «регистрация → аватар отвечает по документам» на стандартных настройках не
проходит до конца**: создание проекта падает на пустом slug, а сгенерированный по дефолту аватар
не отвечает (LLM-модель недоступна). Плюс роль владельца сервиса и пользователя смешаны в коде,
а тарифные энтайтлменты фронт не отражает.

**Светофор сквозных флоу (по живому прогону):**

| Флоу | Статус | Факт |
|---|---|---|
| Регистрация / verify-email | ✅ | resend + обработка истёкшего токена |
| Создание проекта | 🔴 | **422 при пустом slug** (хотя подсказка «оставьте пустым») — L-01 |
| Создание аватара (визард) | ✅ | 4 шага, создаётся |
| Загрузка документов | ✅ | модалка, индексация быстро «Готов» |
| **Тест в чате (aha)** | 🔴 | gated публикацией (403) **и** RAG-модель 404 — L-02/L-03 |
| Выпуск в Telegram | 🟡 | на growth доступен; на free показан без гейта (L-06) |
| Наблюдение (диалоги/сессии) | 🟡 | оператор может отвечать; пустые состояния без объяснения |
| Команда | 🟡 | пустой `/members` — тупик; роли смешаны (R-01) |
| Биллинг/лимиты → заявка | 🟡 | заявка работает; апгрейд без сравнения тарифов (L-08); лимиты ресурсов не enforced (L-07) |
| Разделение ролей оператор↔тенант | 🟡 | у обычного юзера чисто; у saas_admin смешано (R-03) |

**Метрики:** кликов до первого ответа аватара (aha) — **недостижимо на дефолтах** (блокеры L-01/L-02);
после обхода (slug вручную + смена модели + публикация) — ~14 кликов + 4 шага. Активация: **3 блокера
+ 4 обрыва**. Находок: **2 blocker · ~17 major · ~22 minor**.

**Главный вывод по требованиям:** ключевые P0-user-stories (дойти до первого ответа аватара —
ядро ценности) **сейчас не закрыты** из-за L-01/L-02. Это первое, что нужно чинить.

## 2. Бизнес-контекст, акторы, роли

**Продукт:** SaaS для AI-консультантов («аватаров»), отвечающих по документам клиента (RAG) в
Telegram и на сайте. Монетизация — тарифы (токены + фичи), апгрейд заявкой, админ-панель платформы.

**Ценность:** «загрузил документы → аватар консультирует клиентов в Telegram → слежу за диалогами/расходом».

**Роли — две независимые системы `[бэк]`:**
- Платформенная `UserRole`: `saas_admin` (оператор сервиса), `owner`, `manager`, `content_manager`, `client`.
- Проектная `ProjectMemberRole`: `owner`, `admin`, `manager`, `content_manager`, `viewer` (права: manage_avatars/documents/members, view_analytics, manage_settings — `projects/domain/models.py:145`).

| Актор | Цель | Зона |
|---|---|---|
| Гость | понять продукт, зарегистрироваться | `/`, `/login`, `/register` |
| Владелец-тенант (`owner`) | собрать аватара и выпустить | `/projects/*` |
| Член команды | работать в рамках прав | `/projects/[id]/*` |
| **Владелец сервиса** (`saas_admin`) | управлять платформой | `/admin/*` (+ свои проекты — смешано, R-03) |
| Конечный клиент | пишет боту (вне UI) | объект наблюдения |

## 8. Редизайн-рецепт (как сделать просто и удобно)

**North-star:** «довести до первого ответа за 3 шага». Чеклист активации, одно главное действие
на экран, настройки берёт система по дефолту (**но дефолты должны работать** — см. L-01/L-02).

**Целевая IA (R-03/N-01):** вынести админку из общего сайдбара в отдельную operator-зону;
навигацию аватара — в табы; глобальный switcher проекта; развести нейминг (Клиенты / Пользователи
платформы / Профиль · Настройки проекта · Платформа).

**Ключевые ходы (before→after, эскизы — в архивном `UX_ANALYSIS.md` §10):**
1. Онбординг-чеклист «проект → аватар → документы → опубликовать/чат → Telegram» (A-01).
2. Реактивные мосты next-step: после доков «Готов» → «Открыть тестовый чат»; после аватара → «Загрузить документы»; после Telegram → «Открыть @bot» (A-02/03/04).
3. Упрощение создания аватара: 1 поле + «Расширенно» с **рабочими** дефолтами модели (A-05 + L-02).
4. Тарифный гейтинг: хук `usePlanEntitlements()` по `plan_features` → дизейбл/upsell фич вне плана (PL-01), лимиты в точке действия (PL-02), сравнение планов в апгрейде (PL-05/L-08).
5. Живые пустые состояния + объяснения (S-01/S-02).

**Целевые UX-метрики:** кликов до aha ≤6 · обрывов 0 · пунктов сайдбара (админ) ≤8 · пустых-без-CTA 0 · деструктив-без-подтверждения 0.
